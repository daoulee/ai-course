# AI 활용 프로그래밍 수업 작업 규칙

- 작업을 시작할 때 해당 주차의 `SPEC.md`를 먼저 읽고, 요청받은 단계와 파일만 수정한다. Plan에서는 코드를 쓰지 않는다.
- 코드 작성에는 현재 Cline에 설정된 학교 `gemma4`를 사용한다. 별도 Python 스크립트로 모델 API를 직접 호출하지 않는다.
- 파일 수정 도구가 실패하면 오류를 보고하고 멈춘다. `rm`·`touch`로 기존 파일을 지우거나 같은 수정을 무한 반복하지 않는다.
- 명세에 없는 외부 패키지를 설치하지 않는다. 특히 직접 실행하는 `test_calc.py`를 검사하려고 `pytest`를 설치하지 않는다.
- `week04/calc2/` 테스트는 SPEC의 20개 입력과 기대값을 그대로 사용하고, 사례마다 새 `Calculator`를 만든다. 실패를 출력한 뒤 종료 코드 1을 반환한다. 테스트 기대값을 구현에 맞춰 바꾸지 않는다.
- `week04/calc2/`와 `week07/`의 Flet 화면은 각 SPEC의 1.0 뼈대 문법만 사용한다: `ft.run(main)`, `page.window.width/height/resizable`, `ft.Button(content=...)`, `ft.Colors`. `ft.app`, `ft.ElevatedButton`, `ft.colors`, `page.window_width`는 쓰지 않는다.
- 계산 로직과 화면을 분리한다. 계산 테스트 통과와 실제 창 실행·화면 확인을 각각 구분해 보고하고, 실행하지 않은 결과를 성공으로 말하지 않는다.
- 기록에는 실제로 실행한 명령과 결과만 적는다. AI 사용을 숨기거나 직접 작성했다고 허위로 표기하지 않는다. 제출 전에는 작성자가 코드를 설명할 수 있도록 핵심 상태 전이와 예외 처리를 정리한다.
- 사용자가 요청하기 전에는 다른 주차, 개인 보관 파일, Git 커밋·푸시를 건드리지 않는다.
