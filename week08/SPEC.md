# SPEC.md: 주차 요금 계산기

## 1. 개요
사용자가 입차 시각과 출차 시각을 입력하면 주차 요금을 계산하고, 기록을 목록으로 관리하며, 실행 환경의 '오늘' 날짜에 해당하는 요금의 합계를 보여주는 웹 애플리케이션입니다.

## 2. 기술 스택 및 파일 구성
- **언어:** Python
- **UI 프레임워크:** Flet (버전 1.0 뼈대 문법 준수)
- **파일 구조 및 역할:**
    - `week08/SPEC.md`: 동작 규칙 및 테스트 명세
    - `week08/calculator.py`: **핵심 로직 담당.** 입력 정규화(Trim), 유효성 검증, 요금 계산, 목록/합계 필터링 로직을 포함하며, UI 의존성 없이 독립적으로 테스트 가능함.
    - `week08/test_calculator.py`: `calculator.py`의 로직을 검증하는 자동화 테스트. 통과/실패 수 출력 및 종료 코드(0/1) 관리.
    - `week08/main.py`: **UI 담당.** `calculator.py`의 로직을 호출하여 결과를 화면에 표시하고 사용자 입력을 전달함.

## 3. 동작 규칙 (Business Rules)

### 3.1 요금 계산 규칙
- **무료 구간:** 입차 후 30분까지는 0원입니다.
- **유료 구간:** 30분 초과 시, 10분 단위로 500원이 부과됩니다. (10분 미만의 잔여 시간도 10분으로 간주하여 올림 계산)
- **최대 요금:** 하루 최대 요금은 20,000원입니다.

### 3.2 입력 및 유효성 검증 규칙
입력 정규화와 유효성 검증은 `calculator.py`에서 수행하며, `main.py`는 이 결과를 화면에 표시합니다.
- **정규화:** 입력값 앞뒤의 공백은 제거(trim)합니다.
- **형식 검사:** `HH:MM` (24시간제, 반드시 시와 분이 각각 두 자리 숫자여야 함. 예: `09:05`는 허용, `9:5`는 불허하며 자동 보정하지 않음)
- **범위 검사:** `00:00` ~ `23:59` 사이의 유효한 시각이어야 함 (예: `09:65`, `24:00`, `abc` 등은 불허)
- **논리 검사:** 입차 시각 < 출차 시각이어야 함 (자정 넘기는 주차 미지원. 입차와 출차가 같거나 출차가 더 이르면 불허)
- **빈 값 검사:** 입차 또는 출차 필드 중 하나라도 비어 있거나 공백만 있는 경우 불허
- **오류 시 동작:** 검증 실패 시 에러 메시지를 입력창 근처에 표시하며, **검증 실패 시 기록을 추가·삭제·수정하지 않는다. 기준 날짜가 같으면 합계도 유지한다. 날짜가 바뀌었다면 기록은 보존하면서 기준 날짜와 오늘 합계를 갱신한다.**

### 3.3 목록 및 합계 관리 규칙
- **기록 저장:** 계산 성공 시 `[입차, 출차, 주차 시간, 요금, 계산 날짜]`를 목록에 추가합니다.
- **오늘의 합계:** 
    - 목록 중 **실행 환경의 오늘 날짜**와 일치하는 기록의 요금만 합산합니다.
    - 화면에 합계 금액과 함께 **합계 산정 기준이 되는 날짜**를 명시합니다.
    - **갱신 시점:** 화면을 처음 열 때, 계산 버튼을 누를 때(입력 성공 여부와 무관), 기록을 삭제할 때 현재 날짜를 확인하고 합계를 갱신한다. 사용자 조작 없이 자정 변경을 자동 감지하는 기능은 구현하지 않는다.
- **데이터 휘발성:** 프로그램 종료 또는 브라우저 새로고침 시 모든 데이터는 삭제됩니다. 네트워크 끊김 후 재연결 시에도 기록이 초기화됩니다.

### 3.4 출력 형식
- 모든 금액 표시는 천 단위마다 쉼표(`,`)를 포함합니다. (예: `1,500원`, `20,000원`)

## 4. 화면 구성 (UI Layout)
- **상단:** "기준 날짜: [YYYY-MM-DD] | 오늘의 요금 합계: [금액]원"
- **중앙:** 
    - 입차 시각 입력 필드 (`HH:MM`)
    - 출차 시각 입력 필드 (`HH:MM`)
    - 계산 버튼
    - 에러 메시지 표시 영역 (입력 필드 하단)
- **하단:** 
    - 계산 기록 리스트 (입차, 출차, 주차 시간, 요금 표시)
    - 각 행 끝에 '삭제' 버튼 배치

## 5. 테스트 및 검증 계획

### 5.1 자동화 테스트 (`test_calculator.py`)
실행 시 **"통과: n, 실패: m"**을 출력하며, **실패가 있으면 종료 코드 1, 모두 통과하면 0을 반환**합니다.

|:---|:---|:---|:---|:---|:---|

| T2 | 09:00 | 09:30 | 30분 | 0원 | 무료 구간 경계 |

| T4 | 09:00 | 09:41 | 41분 | 1,000원 | 10분 미만 올림 적용 |
| T5 | 09:00 | 13:00 | 240분 | 10,500원 | (240-30)/10 * 500 |
| T6 | 09:00 | 16:00 | 420분 | 19,500원 | (420-30)/10 * 500 |
| T7 | 09:00 | 16:01 | 421분 | 20,000원 | 10분 올림 + 상한 적용 |
| T8 | 09:00 | 16:11 | 431분 | 20,000원 | 상한 도달 후 유지 |

#### [Case 3: 목록 및 합계 관리 (날짜 주입 테스트)]
*테스트 시에는 날짜를 인자로 주입하여 실제 날짜와 무관하게 검증함.*
| ID | 시나리오 | 기록 데이터 (날짜 포함) | 기대 결과 (합계) |
|:---|:---|:---|:---|
| T19 | 여러 날짜 기록 존재 | [D1: 500원, D1: 1000원, D2: 2000원] | D1일 기준 합계: 1,500원 |
| T20 | 중간 기록 삭제 | [D1: 500원, D1: 1000원, D1: 2000원] $\rightarrow$ 1000원 삭제 | D1일 기준 합계: 2,500원 |
| T21 | 모든 기록 삭제 | [D1: 500원] $\rightarrow$ 삭제 | 합계: 0원 |
| T22 | 날짜 변경 시뮬레이션 | D1 기록 존재 $\rightarrow$ 기준일 D2로 변경 시 | 합계: 0원 |

### 5.2 UI/UX 수동 확인 항목
- [ ] **에러 메시지:** 잘못된 형식/빈 값 입력 시 에러 메시지가 나타나는가?
- [ ] **데이터 무결성:** 날짜가 바뀐 뒤 잘못된 입력을 넣었을 때, 기존 기록은 유지되고 합계 기준만 새 날짜로 바뀌는가?
- [ ] **포맷팅:** 모든 금액에 천 단위 쉼표가 적용되었는가?
- [ ] **날짜 표시:** 화면 상단에 기준 날짜가 명확히 표시되는가?
- [ ] **브라우저 동작:** 웹 브라우저에서 정상 실행되며, 새로고침 후 데이터가 초기화되는가?
- [ ] **기록 관리:** 기록 추가와 중간 행 삭제가 올바르게 동작하는가?

- [ ] **재연결 초기화:** 연결이 끊겼다가 다시 연결되면 기록·입력·오류 표시가 초기화되고, 현재 날짜와 합계 0원이 표시되는가?
